# 03 — Roadmap

## Phase 0 — Foundation

Status: **IN PROGRESS**

- [x] utworzenie repozytorium
- [x] inicjalizacja React + TypeScript + Vite
- [x] podstawowy responsive shell
- [x] dokumentacja celu i zakresu
- [x] baseline architektury
- [x] instrukcje dla agentów AI
- [ ] ustalenie pierwszego konkretnego celu publicznej strony
- [ ] ustalenie kierunku wizualnego
- [ ] decyzja dotycząca prywatności repozytorium

## Phase 1 — Discovery & UX

- mapa potrzeb użytkowników
- user journeys dla osoby poznającej grę i właściciela gry
- architektura informacji strony
- lista ekranów / sekcji
- content inventory
- wireframe mobile-first
- decyzje dotyczące CTA
- lista assetów potrzebnych z fizycznej gry

**Exit criterion:** przed implementacją wiemy dokładnie, jakie sekcje powstają, do kogo są skierowane i po co istnieją.

## Phase 2 — Visual System

- przełożenie identyfikacji Quiz Arena na web
- typografia
- paleta
- design tokens
- buttons / cards / sections
- zasady użycia grafik kart i komponentów fizycznych
- motion principles

**Exit criterion:** można zbudować cały Product Website bez wymyślania stylu na każdej sekcji osobno.

## Phase 3 — Product Website MVP

- header / navigation
- hero
- positioning produktu
- jak wygląda rozgrywka
- kluczowe wyróżniki
- komponenty fizyczne
- skrócone zasady
- FAQ
- footer
- metadata / social sharing
- optymalizacja mobile
- performance pass
- accessibility pass

## Phase 4 — Launch Readiness

- final copy
- final asset compression
- favicon / social preview
- analytics decision
- hosting
- domena
- smoke tests
- production deployment

## Phase 5 — Rules & Support Hub

Zakres do zdefiniowania po pierwszych testach Product Website.

## Phase 6 — Companion App Discovery

Nie rozpoczynać implementacji przed osobnym discovery. Najpierw należy zidentyfikować realne problemy podczas fizycznej rozgrywki, które aplikacja ma rozwiązać.

## Zasada roadmapy

Nie przeskakujemy do kolejnej fazy tylko dlatego, że technicznie potrafimy coś zbudować. Każdy większy element powinien odpowiadać na konkretny problem użytkownika albo cel produktu.
