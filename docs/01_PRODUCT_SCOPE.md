# 01 — Product Scope

## Podejście

Nie budujemy od razu wszystkiego, co potencjalnie może znaleźć się na stronie. Projekt rozwijamy warstwami, każda kolejna musi mieć uzasadnienie użytkowe.

## Phase 0 — Foundation

Cel: stworzyć stabilny fundament techniczny i produktowy.

Zakres:

- repozytorium i standardy pracy,
- React + TypeScript + Vite,
- podstawowa struktura dokumentacji,
- placeholder landing page,
- ochrona prywatnych treści gry,
- zasady dla agentów AI.

## Phase 1 — Product Website MVP

Cel: strona, którą można realnie pokazać osobie niezwiązanej z projektem.

Planowany zakres:

- hero i jasne value proposition,
- sekcja „jak działa Quiz Arena”,
- prezentacja charakteru rozgrywki,
- liczba graczy / orientacyjny czas / typ doświadczenia,
- prezentacja fizycznych komponentów,
- najważniejsze wyróżniki gry,
- skrócone zasady,
- FAQ,
- pełna responsywność,
- przygotowanie pod podstawowe SEO i social sharing.

## Phase 2 — Rules & Support Hub

Możliwy zakres:

- pełniejsze zasady gry,
- wyjaśnienia trybów i ikon,
- FAQ sytuacji spornych,
- materiały do pobrania,
- changelog zasad,
- numer wersji instrukcji.

## Phase 3 — Companion App MVP

Zakres zostanie zdefiniowany osobno. Potencjalne funkcje mogą obejmować narzędzia ułatwiające prowadzenie partii, ale nie należy implementować ich przed zatwierdzeniem konkretnego user flow.

## Phase 4 — Rozwój produktu cyfrowego

Dopiero po testach wcześniejszych etapów można oceniać sens takich funkcji jak:

- profile / konta,
- historia rozgrywek,
- statystyki,
- aktualizowane pakiety treści,
- funkcje społecznościowe,
- sklep lub płatne rozszerzenia.

## Kluczowe ograniczenia

1. Strona nie może ujawniać pełnej bazy pytań.
2. Pierwsza wersja nie wymaga backendu.
3. Mobile jest równorzędnym targetem, nie późniejszym dodatkiem.
4. Marketingowy przekaz musi wynikać z realnych mechanik gry, a nie z generycznych sloganów.
5. Companion app nie może niepotrzebnie przenosić uwagi graczy z planszy/kart na telefon.

## Otwarte decyzje produktowe

Do rozstrzygnięcia przed Phase 1:

- główny cel pierwszej publicznej wersji strony,
- docelowy charakter wizualny i design system,
- czy strona ma być wyłącznie informacyjna czy od początku przygotowana do funkcji companion,
- jakie dokładnie materiały z fizycznej gry mogą być publicznie pokazane,
- docelowy hosting i domena.
